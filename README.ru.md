# tg-skill

**Telegram для ИИ-агентов в одном Python-файле: твой аккаунт и твой бот, а уровень доступа ты выдаёшь при каждом вызове.**

[English version](README.md)

```text
/telegram              → read: непрочитанное, история, поиск, анализ каналов
/telegram full         → read + отправка от твоего имени (сначала dry-run)
/telegram bot          → твой бот: уведомить, прислать файл, дождаться твоего ответа
```

- **Обе стороны Telegram в одном скилле.** *Аккаунт* через [Telethon](https://github.com/LonamiWebs/Telethon) читает всё, что видишь ты, и пишет от твоего имени. *Бот* через Bot API работает на чистой stdlib и нужен для уведомлений, файлов и удалённого управления.
- **Доступ выдаётся при каждом вызове.** По умолчанию `read`. Для отправки нужен `/telegram full`, и каждая отправка сначала проходит как dry-run, где видно, кому именно уйдёт сообщение. Жёсткий список разрешённых чатов задаётся в `TG_ALLOWED_CHATS`.
- **Только Python.** Один файл `skills/telegram/scripts/tg.py`. `pip install telethon` нужен только для режима аккаунта. Без MCP-сервера, Node и демонов.
- **Работает везде, где работают скиллы.** Claude Code, любой агент с поддержкой Agent Skills, облачный чат с выполнением кода (см. [где работает](#где-работает)).

## Быстрый старт

```bash
git clone https://github.com/EZHOWWW/tg-skill && cd tg-skill
ln -s "$PWD/skills/telegram" ~/.claude/skills/telegram     # доступен в каждой сессии Claude Code
pip install telethon

cp skills/telegram/.env.example skills/telegram/.env       # заполни, подсказки внутри
python3 skills/telegram/scripts/tg.py login                # один раз: код из Telegram, печатает TELEGRAM_SESSION_STRING=...
#   вставь эту строку в skills/telegram/.env
python3 skills/telegram/scripts/tg.py doctor               # {"bot": {"ok": true}, "account": {"ok": true}}
```

Дальше в любой сессии:

```text
/telegram            что непрочитанного от команды за сегодня?
/telegram            разбери @some_channel с 2026-10-01
/telegram full       ответь Саше, что отчёт пришлю завтра
/telegram bot        когда тесты закончатся, пришли мне лог
```

## Режимы доступа

| Режим | Что разрешено | Для чего |
|---|---|---|
| `read` (по умолчанию) | `me`, `chats [--unread]`, `read CHAT [--since/--search]` | разбор входящих, поиск, анализ каналов |
| `full` | `read` + `send` от твоего имени (текст, файл, ответ) | переписка с коллегами |
| `bot` | `bot-send`, `bot-file`, `bot-wait` через твоего бота | уведомления, управление с телефона |

Режимы комбинируются: `/telegram full,bot`. CLI проверяет режим сам
(`denied: 'send' needs mode 'full'`), а скилл запрещает агенту повышать себе доступ.
`send` без `--yes` только печатает `{"dry_run": true, "to": "<имя адресата>", ...}` и выходит с кодом 2.

## Команды

```bash
tg.py doctor                                   # что работает в этом окружении (имена переменных, без значений)
tg.py chats --unread | --query "team"
tg.py read @alice --limit 20
tg.py read -1001234567890 --since 2026-10-01   # весь период, для анализа
tg.py read all --search "счёт"                 # глобальный поиск
tg.py --mode full send @alice "Принял" --yes
tg.py --mode full send @alice - --yes < reply.txt
tg.py --mode bot bot-send "Сборка зелёная"
tg.py --mode bot bot-file report.pdf --caption "Недельный"
tg.py --mode bot bot-wait --timeout 600        # ждёт твоего сообщения боту; файлы падают в inbox/
```

Весь вывод в формате JSON lines: агент читает его напрямую или сохраняет в файл.

**Удалённое управление.** Агентом можно управлять с телефона, без экрана. Цикл такой:
`bot-wait`, затем работа, затем ответ через `bot-send`, затем снова `bot-wait`.
Один токен бота может опрашивать только один процесс одновременно.

## Где работает

| Окружение | Бот | Аккаунт |
|---|---|---|
| Твоя машина: Claude Code, Codex CLI, любой агент с shell | ✅ | ✅ |
| Облачные песочницы чатов с выполнением кода (claude.ai и другие) | ✅, если в сетевых настройках песочницы разрешён `api.telegram.org` | ⚠️ обычно ❌ |

Облачные песочницы пускают трафик через HTTPS-прокси со списком разрешённых доменов и
блокируют прямой TCP. Bot API работает по обычному HTTPS и проходит. Протокол аккаунта
(MTProto) подключается напрямую к IP серверов Telegram и обычно не проходит.
`tg.py doctor` показывает, какой у тебя случай. Загружается бандл из `scripts/package.sh` (см. ниже).

## Модель безопасности

**Прочитай это, прежде чем класть секреты в облачный чат.**

| Секрет | Что может владелец | Как отозвать |
|---|---|---|
| `TELEGRAM_SESSION_STRING` | Всё, что можешь ты: читать все чаты, писать и удалять от твоего имени, видеть коды входа (без 2FA это захват аккаунта) | Telegram → Настройки → Устройства → завершить **tg-skill** |
| `TELEGRAM_BOT_TOKEN` | Управлять одним этим ботом | @BotFather → `/revoke` |
| `TELEGRAM_API_ID` / `API_HASH` | Сами по себе ничего (идентифицируют твоё приложение) | — |
| телефон, user id | Персональные данные | — |

Если загрузить файл с секретами в облачный чат, он окажется доступен тремя путями:

1. **Хранение.** Провайдер хранит файлы скилла по своей политике хранения.
2. **Переписка.** Всё, что агент выведет, остаётся в истории чата и в экспорте.
3. **Prompt injection** (главная угроза). Агент читает чужие чаты, держит твои секреты и может отправлять сообщения. Это все три части [«смертельной тройки»](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/). Одно специально составленное сообщение в канале, который ты читаешь, может попросить агента что-то переслать.

**Вывод.** Токен бота в облачном чате это приемлемый риск: доступ ограничен одним ботом, а отзывается он за секунды. **Сессия основного аккаунта неприемлема.** Загрузить её значит отдать аккаунт провайдеру и любому, кто может написать в читаемый тобой чат.

Что делает tg-skill:

- **`read` по умолчанию.** Для записи нужен явный `/telegram full`, каждая отправка сначала идёт как dry-run.
- **Список `TG_ALLOWED_CHATS`.** Запись возможна только в перечисленные чаты. Это закрывает сценарий «отправь это @attacker».
- **Секреты не выводятся.** CLI не печатает их нигде: URL бота содержит токен и в вывод не попадает, `doctor` показывает только имена переменных. Отправлять `.env`, `*.session` и файлы ключей CLI отказывается.
- **Именованная сессия.** В «Устройствах» она видна как **tg-skill**, её можно завершить, не выходя на других устройствах.
- **Бандлы по умолчанию только с ботом.** `scripts/package.sh --personal` кладёт **только ключи бота**. Ключи аккаунта добавляются только флагом `--with-account`, с предупреждением.

Что стоит сделать тебе:

- **Отдельный аккаунт для облачных чатов.** Если там нужен режим аккаунта, заведи второй аккаунт Telegram и добавь его только в нужные чаты.
- **2FA.** Включи двухэтапную проверку и *автоматическое завершение неактивных сеансов*.
- **Локально безопаснее всего.** Полный режим аккаунта держи на своей машине (Claude Code). Файл с секретами не покидает диск, модель видит только вывод команд.
- **Не шифруй файл паролем.** Пароль пришлось бы вводить в тот же чат, так что защиты это не даёт.

## Сборка для загрузки в чат

```bash
scripts/package.sh                                # dist/tg-skill.skill: без секретов, можно делиться
scripts/package.sh --personal                     # + токен бота, user id, allowlist
scripts/package.sh --personal --with-account      # + сессия аккаунта (см. раздел выше)
```

## Аналоги и зачем это всё

Проверено в октябре 2026. Все проекты хорошие, но ни один не закрывает сразу *аккаунт + бот + только Python + права на каждый вызов + работу как обычный скилл*.

| Проект | Что это | Чего не хватает |
|---|---|---|
| [chigwell/telegram-mcp](https://github.com/chigwell/telegram-mcp) (1.7k★) | MCP-сервер на Python, 80+ инструментов, аккаунт | Это MCP, а не скилл: для веб-чата нужен свой HTTP-сервер и поддержка коннекторов. Бота нет. Большой набор инструментов занимает контекст. (Наши режимы вдохновлены его `TELEGRAM_EXPOSED_TOOLS=read-only`.) |
| [jackwener/tg-cli](https://github.com/jackwener/tg-cli) (292★) | CLI на Python + SKILL.md, локальная синхронизация в SQLite | Только аккаунт, бота нет. У `send` нет подтверждения и режимов доступа. Заточен под синхронизацию и архив. |
| [devxoul/agent-messenger](https://github.com/devxoul/agent-messenger) (228★) | CLI для многих мессенджеров, аккаунт (TDLib) + бот | Node/Bun и нативная TDLib. Ключи лежат в `~/.config` и не переносятся в песочницу чата. Нет разграничения прав. |
| [beautyfree/telegram-agent](https://github.com/beautyfree/telegram-agent) | CLI на Node + скилл (GramJS) | Node 20+, только аккаунт, нет жёсткого режима «только чтение». GPL-3.0. |
| [awrshift/skill-telegram](https://github.com/awrshift/skill-telegram) | Скилл на Python (Telethon) | Только чтение по замыслу: отправки и бота нет. |
| [b1rd33/tg-cli](https://github.com/b1rd33/tg-cli) | CLI на Python с жёсткими гейтами записи | Отличная модель безопасности, но бота нет, а команд 62. |
| [Telegram-канал Claude Code](https://code.claude.com/docs/en/channels) (официальный) | Мост от бота в запущенную сессию Claude Code | Только бот, только Claude Code + Bun, research preview. Твои чаты не читает. |
